# معماری طراح خبر

## اصل محتوایی

طراح خبر متن را بازنویسی نمی‌کند. تیتر، روتیتر، زیرتیتر، کپشن و منبع فقط از خروجی تأییدشده‌ی قبلی دریافت می‌شوند. در حالت «فقط تیتر»، هیچ کپشن یا متن تازه‌ای وارد طرح نمی‌شود.

## اجزا

```text
Telegram Mini App (ادمین)
        │ درخواست امضاشده
        ▼
Design API ─────► PostgreSQL (درخواست، وضعیت، metadata)
        │
        ├───────► Object Storage (لوگو، فونت، عکس ادمین، خروجی)
        ├───────► Renderer (SVG/RTL/Persian fonts/brand layers)
        └───────► n8n (job orchestration, AI, notifications, data adapters)
```

Mini App رابط کاربری است و n8n موتور هماهنگ‌کننده. فایل‌های برند نباید در فایل‌سیستم محلی n8n یا داخل خود ورک‌فلو نگه‌داری شوند.

## ویدیوی چندبخشی

ویدیوساز برای هر خط اجرا یک سکانس ۸ثانیه‌ای پایدار می‌سازد. پروژه پیش از مصرف اعتبار ارائه‌دهنده ذخیره می‌شود، هر سکانس شناسه و وضعیت مستقل دارد و فریم پایانی سکانس قبل لنگر تداوم سکانس بعد است. پس از تکمیل همهٔ سکانس‌ها، Worker آن‌ها را با ffmpeg یکپارچه و برند را در پس‌تولید اضافه می‌کند.

تصاویر مرجع دو دامنه دارند: `studio` برای کاراکتر و لوکیشن ثابتِ تأییدشده و `project` برای فایل موقتِ متعلق به همان کاربر. آپلود فایل‌های پروژه چندتایی و فایل‌به‌فایل است تا درصد پیشرفت، ذخیرهٔ امن و خطای هر فایل مستقل بماند. هر پرامپت حداکثر سه مرجع نقش‌محور دارد.

کاربر پیش از عملیات، موتور خروجی را بین Gemini Omni Flash و Veo 3.1 انتخاب می‌کند. دکمهٔ «ساخت پرامپت» یک بستهٔ قابل‌انتقال مخصوص همان موتور می‌سازد: نسخهٔ Gemini Omni برای استدلال چندرسانه‌ای، ثبات کاراکتر و تغییر پرسپکتیو؛ یا نسخهٔ Veo 3.1 برای برداشت ۸ثانیه‌ای و حداکثر سه مرجع. Gemini تصاویر واقعی را همراه با قرارداد پروژه می‌بیند و برای هر سکانس، سوژه، کنش و میزانسن، محیط، سبک، قاب/زاویه/لنز/حرکت دوربین، ترکیب‌بندی، نور و رنگ، ضرب‌آهنگ زمانی، دیالوگ و صدا، تداوم و موارد منفی را مشخص می‌کند. نام فایل‌های مرجع در متن قفل می‌شود و همان فایل‌ها با همان نام به‌صورت تکی یا ZIP قابل دانلودند.

تا زمانی که AvalAI از Gemini Omni Flash پشتیبانی نکند، انتخاب Omni فقط دکمهٔ ساخت پرامپت را فعال نگه می‌دارد و ساخت مستقیم ویدیو هم در UI و هم در Gateway مسدود است. انتخاب Veo 3.1 هر دو عملیات را فعال می‌کند و Worker دقیقاً پرامپت Veo ذخیره‌شده را مصرف می‌کند.

## نقش مدل‌ها

| کار | مدل | مجاز/غیرمجاز |
|---|---|---|
| متن اصلی خبر و تیتر | `gemini-2.5-flash-lite` | پیش‌فرض اقتصادی Reporter؛ بازنویسی فقط پیش از ورود به طراح خبر |
| خبر مهم یا حساس | `gpt-5.4-mini` | گزینهٔ کیفیت بالاتر؛ انتخاب صریح ادمین |
| تصویر زمینه/ایده‌پردازی تصویری | `gpt-image-2` | لوگو و حروف فارسی نباید به مدل سپرده شود |
| تصویر پیش‌فرض اقتصادی | `gemini-3.1-flash-lite-image` | طرح‌های روزمره و پیش‌نمایش؛ پیش از استفادهٔ گسترده با تیترهای فارسی واقعی ارزیابی شود |
| تصویر نهاییِ حساس | `gemini-3.1-flash-image` | تیترهای حساس، ارجاع تصویری دشوار یا خروجی‌ای که نیاز به دقت بیشتر دارد |
| کارگردانی و نگارش پرامپت ویدیو | `KALAM_VIDEO_PROMPT_MODEL` (پیش‌فرض مدل Gemini متنی سامانه) | ورودی چندتصویری، خروجی JSON و بازبینی ادمین پیش از تولید |
| تولید سکانس ویدیو | `veo-3.1-fast-generate-preview` / `veo-3.1-generate-preview` | هر سکانس ۸ ثانیه، حداکثر سه مرجع و تداوم با فریم پایانی |

## رسانه و رنگ

| رسانه | رنگ پایه |
|---|---|
| کلام تازه | قرمز سازمانی؛ مقدار دقیق پس از دریافت Brand Kit |
| کلام تازه گلبهار | آبی روشن؛ مقدار دقیق پس از دریافت Brand Kit |
| کلام تازه چناران | سبز؛ مقدار دقیق پس از دریافت Brand Kit |

در خبرها، تم رسانه اولویت دارد. آیتم‌های غیرخبری می‌توانند رنگ ثابت اختصاصی داشته باشند، اما لوگو و هویت رسانه تغییر نمی‌کند.

## روش استفاده از عکس ادمین

1. `preserve`: همه‌ی عکس‌ها واقعاً در طرح استفاده می‌شوند؛ فقط crop، چیدمان، اصلاح نور و ارتقای کیفیت مجاز است.
2. `reference`: همه‌ی عکس‌ها به مدل به‌عنوان مرجع الهام داده می‌شوند؛ خروجی می‌تواند تصویر تازه باشد.
3. `multi_slide`: ادمین انتخاب می‌کند عکس‌ها به گزارش تصویری چنداسلایدی تبدیل شوند.
4. `edit_existing`: تصویر یا تصاویر خروجی قبلی/انتخاب‌شده با قابلیت رسمی image-edit مدل انتخاب‌شده و با یک دستور ویرایش مشخص اصلاح می‌شوند. شناسهٔ پروژهٔ مبنا و فایل‌های اصلی به job متصل می‌مانند.

انتخاب تک‌طرح یا اسلایدی همیشه با ادمین است؛ سیستم خودسرانه عکس‌ها را حذف نمی‌کند.

## کتابخانه و پروژه‌ها

هر درخواست در Gateway به‌عنوان یک پروژه با درخواست اصلی، فایل‌های ورودی، دارایی‌های انتخاب‌شده و وضعیت صف ثبت می‌شود. کتابخانه دو بخش دارد: دارایی‌های تأییدشدهٔ رسانه و پروژه‌های قبلی. انتخاب یک پروژهٔ قبلی فقط metadata و فایل اصلی آن را به حالت `edit_existing` منتقل می‌کند؛ تصویر از روی preview یا فایل فشرده دوباره ساخته نمی‌شود.

## قالب‌های نسخه اول

### خبری

- استوری خبر
- پست خبر
- گزارش تصویری
- استوری ویدیویی با جای خالی ویدیو
- پیام مردمی
- اینفوگرافی

حالت متن خبر: فقط تیتر، روتیتر + تیتر، تیتر + زیرتیتر، تیتر دوبخشی، یا تیتر + کپشن. شکست تیتر دوبخشی صرفاً صفحه‌آرایی است و کلمات را تغییر نمی‌دهد.

### ثابت و تعاملی

- صبح بخیر گلبهار و چناران
- صبح بخیر پیج کلام
- طلا و ارز: دلار، یورو، سکه امامی، طلای ۱۸ عیار و بیت‌کوین؛ همه به ریال همراه منبع و زمان
- شبانه، ترفند خانه‌داری، معمای تصویری و طبیعت‌گردی
- استوری و پست نظرسنجی
- استوری ورزشی

## کتابخانه دارایی

فعلاً فایل‌های اولیه در مسیر محلی `brand-assets/` قرار می‌گیرند. در محیط عملیاتی به Object Storage منتقل می‌شوند و فقط metadata در پایگاه داده می‌ماند.

برای هر رسانه لازم است: لوگوی PNG شفاف و SVG، رنگ‌های دقیق، فونت مجاز، تصویر مجریان با نام، و قالب یا نمونه‌ی طراحی تأییدشده.

فهرست اولیهٔ کتابخانه: سه لوگوی اصلی، فایل فونت دارای مجوز وب، دو تصویر مجری و تصاویر محیط‌های استودیو (استودیوی اصلی، میز خبر و نمایشگر). هر فایل شناسهٔ پایدار، مالک، رسانه، نسخه، حق استفاده و checksum دارد؛ Mini App فقط شناسه را ارسال می‌کند.

## سیاست خطا و هزینه

- هر درخواست مدل شامل `requestId`، مدل، هزینه، زمان و وضعیت است.
- سه تلاش با فاصله برای خطای موقت وجود دارد.
- کاربر فقط پیام دسته‌بندی‌شده می‌بیند؛ جزئیات فنی برای مدیر ثبت می‌شود.
- انتخاب «سریع و اقتصادی»، «حرفه‌ای» و «تصویر حرفه‌ای» در UI نمایش داده می‌شود؛ نام خام مدل فقط در حالت پیشرفته‌ی ادمین قابل مشاهده است.

## قرارداد API و امنیت

Mini App فقط `telegramInitData` و بدنهٔ درخواست را به `POST /design-requests` می‌فرستد. endpoint در نسخهٔ اول یک Webhook n8n پشت یک gateway است. gateway باید پیش از ایجاد job این مراحل را انجام دهد:

1. امضای `initData` را با Bot Token تلگرام اعتبارسنجی کند؛ `initDataUnsafe` مرورگر قابل اعتماد نیست.
2. شناسهٔ کاربر را با فهرست ادمین‌ها تطبیق دهد و مقدار `adminUserId` ارسالی مرورگر را نادیده بگیرد.
3. بدنه را با `contracts/design-request.schema.json` اعتبارسنجی و برای آن `requestId` بسازد.
4. تصویرها را جداگانه در Object Storage آپلود کند؛ Mini App نباید فایل یا کلید سرویس را به n8n بفرستد.
5. فقط metadata و URLهای کوتاه‌عمر را به workflow طراحی n8n ارسال کند.

تا زمانی که `VITE_DESIGN_API_URL` تنظیم نشده، Mini App فقط پیش‌نمایش request را نمایش می‌دهد و هیچ داده‌ای ارسال نمی‌کند.
